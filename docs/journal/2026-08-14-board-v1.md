# Werkbank v1 — ticket store, Kanban board, dispatch skills

## What was asked

"Something like Jira for Claude Code": user or an agent writes tickets, assigned
agents work them off. Interview answers (AskUserQuestion): Kanban board in the
browser from the start; agents dispatch on demand only (no daemon); first target
project is this repo itself.

## What I did

- `docs/dev/stack.md` — decision record: markdown files + stdlib Python, no deps.
- `src/werkbank/store.py` + `tests/test_store.py` (8 tests, `python3 -m unittest
  discover -s tests`, all green). Tickets: `tickets/WB-<n>-<slug>.md`, flat
  frontmatter, body sections `## Beschreibung` / `## Ergebnis`. Statuses
  `offen|in_arbeit|review|erledigt`, priorities `hoch|normal|niedrig`.
- `src/werkbank/server.py` + `board.html` — ThreadingHTTPServer on 127.0.0.1:8765
  (config.json), JSON API (GET list, POST create, POST /api/tickets/WB-n partial
  update), vanilla-JS board: 4 columns, drag&drop, create/edit dialogs, 5s poll.
  board.html is re-read per GET; only server.py changes need a restart.
- Project skills: `start-board` (idempotent start/stop/restart, log at
  /tmp/werkbank-board.log), `work-tickets` (dispatch flow; agents stop at `review`,
  never set `erledigt`; failures go to `review` with the blocker in `## Ergebnis`).
- User doc `docs/user/board-und-tickets.md`, CHANGELOG entries, indexes updated.
- Commits: `Add ticket store…`, `Add Kanban board…`, plus this docs/skills commit.

## What I tried that didn't work — and why

- **Headless Firefox screenshot of the board.** First run exit code 2 (likely the
  running desktop Firefox holding the profile), second run with `--profile ffprof`
  hung until the 60 s timeout, no PNG. Gave up — verified instead via curl
  (create/move/reject-invalid all correct, GET / → 200) and `node --check` on the
  page script (OK). The UI itself has NOT been visually verified; user will see it
  on first open.

## Decisions made

- Files as source of truth, board as UI on top — survives without any service,
  agents edit tickets with plain file tools (rejected DB/framework, see stack.md).
- `erledigt` is user-only; agents park results in `review` — keeps the human
  approval step Jira-like and makes silent failures impossible (skill rule: a
  failed ticket must not sit in `in_arbeit`).
- On-demand dispatch via the `work-tickets` skill, no watcher daemon (user's
  explicit choice).
